# Build Verification Guide

This document explains how to verify that the documentation workflow builds correctly and how to capture screenshots of the built site.

## Re-running the Documentation Workflow

The documentation is built automatically by GitHub Actions when changes are pushed to the `master` branch or to documentation-related files.

### Manual Workflow Trigger

You can manually trigger a documentation build:

1. Go to the repository on GitHub
2. Click on the **Actions** tab
3. Select the **docs** workflow from the left sidebar
4. Click the **Run workflow** button (top right)
5. Select the branch you want to build from
6. Click **Run workflow**

### Monitoring the Build

After triggering the workflow:

1. The workflow will appear in the list of workflow runs
2. Click on the run to see detailed progress
3. The build typically takes 5-15 minutes depending on cache hits
4. Look for any errors in the **Build Sphinx (HTML)** step

### Build Output Artifact

After a successful build:

1. The HTML output is uploaded as a Pages artifact
2. If deploying to GitHub Pages is enabled, the site will be deployed automatically
3. Screenshots of key pages are generated in the **Generate screenshots** step
4. These screenshots are included in the Pages artifact under `screenshots/`

### Expected Output Location

- **HTML files**: `docs/_build/html/` (in the artifact)
- **Screenshots**: `docs/_build/html/screenshots/` (in the artifact)
- **Deployed site**: `https://lukaszj321.github.io/otcv8-dev` (if Pages deployment is active)

## Adding Screenshots to the Repository

Screenshots generated by the CI workflow can be stored in this repository for reference and verification purposes.

### Screenshot Storage Location

Store screenshots in: `docs/authoring/screenshots/`

### Naming Convention

Use the following naming pattern:
```
build-YYYYMMDD-<branch>.png
```

Examples:
- `build-20251102-master.png` - Main documentation build from master branch
- `build-20251102-fix-shader-docs.png` - Build from a specific fix branch

### How to Add Screenshots

#### From CI Artifacts (Recommended)

1. After a successful workflow run, go to the workflow run page
2. Scroll down to the **Artifacts** section
3. Download the **github-pages** artifact
4. Extract the archive and navigate to the `screenshots/` directory
5. Rename and copy relevant screenshots to `docs/authoring/screenshots/` following the naming convention above
6. Commit and push the screenshots to the repository

#### Manual Screenshots

If you need to capture screenshots manually:

1. Build the documentation locally:
   ```bash
   cd docs
   pip install -r requirements.txt
   sphinx-build -b html . _build/html
   ```

2. Open the built site in a browser:
   ```bash
   # Linux/Mac
   open _build/html/index.html
   
   # Or start a local server
   python -m http.server 8000 --directory _build/html
   ```

3. Take screenshots of important pages (homepage, API docs, etc.)
4. Save them to `docs/authoring/screenshots/` with the proper naming convention
5. Commit and push to the repository

### Screenshot Guidelines

- **Resolution**: Preferably 1920x1080 or 1920x1200 for full-page captures
- **Format**: PNG (for better text clarity)
- **Content**: Focus on key pages that demonstrate the build works correctly:
  - Homepage/index
  - API documentation pages
  - Authoring guide pages
  - Any pages that were fixed or modified
- **File size**: Try to keep individual screenshots under 500KB (use PNG compression if needed)

## Verifying the Build

### Key Checks

When verifying a documentation build:

1. **Build completes without errors** - Check workflow logs for any fatal errors
2. **All pages render correctly** - No broken layouts or missing styles
3. **Code blocks display properly** - Especially important for syntax highlighting
4. **Mermaid diagrams render** - Check that diagrams appear and are readable
5. **Links work** - Internal navigation and cross-references function
6. **Search functionality** - The search index is built and works

### Common Issues

- **Sphinx errors**: Check `sphinx-build` output in the workflow logs
- **Pygments lexing errors**: Usually related to code blocks with unusual syntax
- **Mermaid rendering**: Verify JavaScript is loading and diagrams are valid
- **Missing pages**: Check for broken toctree references in index files
